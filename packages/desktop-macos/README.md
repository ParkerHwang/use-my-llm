# use-my-llm for macOS

The menu bar app starts the use-my-llm bridge on `127.0.0.1:43189`. It supports Apple Silicon and macOS 13.5 or later.

1. Download the notarized Apple Silicon ZIP from the [preview release](https://github.com/ParkerHwang/use-my-llm/releases/tag/v0.1.0). The v0.1.0 archive is `use-my-llm-macos-arm64.zip` and the app inside is **use-my-llm.app**. Unzip the app and open it. When possible, the first launch copies the app into your `~/Applications` folder and starts that copy.
2. Select the menu bar item to see whether the bridge is running. The v0.1.0 app labels that item **use-my-llm**. If it stopped, check whether another instance is using port `43189` and select **Start Bridge** to try again.
3. Return to the website you want to connect and use its pairing flow. The app can be started by `localhostagent://start`. The website still needs your approval on the local pairing page.

The app includes Node.js and the bridge. Install and sign in to any available provider CLI separately. The menu bar status reports the bridge listener. Provider availability is reported by the bridge after pairing. Quit the app from the menu bar to stop the bridge and revoke its in-memory sessions.

To update an existing app, quit it and replace your copy in Applications with the new version. First-launch installation preserves any copy already installed there. A build from this repository installs as `~/Applications/use-my-llm.app` and does not replace `~/Applications/LocalHostAgent SDK.app`. Quit the older app before starting the new one so they do not both try to use port `43189`.

## Share local context

In a build with protocol v1.1, open **Shared Context…** from the menu bar. Select an app, project and item. For conversations, choose a range of messages or the whole text copy when available. Enter the website origin and use **Review Sharing…** to inspect the redacted text and approve the share. **Manage Sharing…** lists each website and revokes its snapshots and local copies. **Import Export ZIP…** adds an official Claude Desktop export to the local picker.

## Claude sign-in

Choose **Connect Claude Subscription…** from the menu bar. Terminal opens the official Claude Code sign-in flow; complete the subscription OAuth sign-in in the browser. Reopen the menu to refresh the connection indicator. The app’s bridge and the terminal CLI use the same private data directory by default. The official Claude Code CLI must be installed separately.

The menu shows **Claude: Subscription connected**, a sign-in requirement, **API key mode**, or **Off**. **Use Claude API Key** switches the persisted local mode; supply `ANTHROPIC_API_KEY` in the app process environment when launching it for that mode. The app does not collect API keys in a dialog or place them in a Terminal command. **Disconnect Claude Subscription** logs out only the bridge-owned Claude login and disables Claude. **Turn Claude Off** disables the provider without logging out. Changes apply to subsequent bridge requests; no restart is needed.

Subscription usage counts against your Claude plan limits. Sign-in does not share existing sessions or memory. Use **Shared Context…** to choose and approve redacted snapshots for each exact website. Conversation continuation uses a copy in bridge-owned storage. Memory, instructions and project context require their own selection. Existing Claude files and the original project stay untouched; revoking sharing and disconnecting a provider are separate actions.

Start the bridge from a terminal for the optional Antigravity provider modes. The app and CLI use the same context store by default. See [Security](../../SECURITY.md) for the sharing and provider boundaries.

## Build a local preview

On an Apple Silicon Mac, install Node.js 22 or later, Python 3.10 or later and the Xcode Command Line Tools. From the repository root, run:

```sh
npm ci
npm run build --workspace @use-my-llm/bridge
python3 packages/desktop-macos/build.py
```

Build the bridge before packaging; the app includes only the compiled runtime and Python worker, not TypeScript sources, development dependencies, source maps, or local configuration. The packaging step rejects missing runtime files, symbolic links in the bridge output, and runtime dependencies. The app includes the repository license and Node.js license.

The build creates `dist/desktop-macos/use-my-llm.app` and `dist/desktop-macos/use-my-llm-macos-arm64.zip`. To build again, choose a new directory with `--output`. The build downloads the Apple Silicon Node.js 24.22.2 archive and verifies it against the pinned release SHA-256. You can supply the same archive locally with `--node-archive`. The bundle includes Node.js's license. [Node.js release checksums](https://nodejs.org/en/blog/release/v24.22.2#shasums)

The ZIP generated by this build script is ad-hoc signed for local development. The ZIP in the preview release was separately Developer ID signed, notarized by Apple, and checked with Gatekeeper. A downloaded first launch on a separate Mac has not yet been verified.

## Integration

The executable starts the bundled `Contents/Resources/node` with `Contents/Resources/app/packages/bridge/dist/cli.mjs`. The app treats the child as ready only after it emits the exact line `LOCALHOST_AGENT_READY http://127.0.0.1:43189`. The `localhostagent://start` link carries no site or provider parameters. [Browser-to-bridge protocol](../../docs/PROTOCOL.md)

The bundle includes the Google SDK adapter's `dist/providers/google_sdk.py` worker. The menu bar app starts the bridge with its default configuration. To use the optional Antigravity API adapter, start the bridge from a terminal with `--enable-antigravity-api` and configure Python and Gemini authentication locally.
